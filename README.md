### 🔎 [Semantic Search & Fuzzy Clustering API](https://github.com/tejashri-del098/Sematic_Search_system)
`Python` `FastAPI` `FAISS` `sentence-transformers` `scikit-learn` `Docker`

Semantic retrieval with a **semantic cache written from scratch** — because no key-value store can compare keys by distance.

- Cache keys are 384-dim unit vectors matched by dot product, with **LRU eviction at 10,000 entries**.

- Tuned the similarity threshold by sweeping **0.70–0.95**, tracking false positives as a separate metric from hit rate.

## ✍️ How I Work

> **Baseline → Hypothesis → Experiment → Number → Written trade-off.**

1. **Measure before optimizing.** DistributedCache's 5.37× win started with a benchmark showing throughput going the *wrong* way.
2. **Distrust the flattering metric.** A 99%-accurate fraud model detecting zero fraud, and a +14.2pp lift hiding under a −3.0pp headline, both came from questioning the number that looked fine.
3. **Ship the harness with the claim.** 510 tests for Vasool, 341 for Pramaan, 168 for NameForge, 153 for CollabSync — reproducibility is part of the deliverable.
4. **Write down what was rejected.** Every project dossier records the alternatives considered and why they lost.
